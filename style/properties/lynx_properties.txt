# CSS containment (css-contain-2) is a deliberate lynx-vello extension beyond
# Lynx's own property index (Lynx has no containment property at all): a real
# W3C feature (https://drafts.csswg.org/css-contain-2/) that the web-target
# bundles already get via browser passthrough and the native engine wires up to
# bound relayout / damage propagation. Seeding the `contain-intrinsic-size`
# shorthand lets the closure pull in its contain-intrinsic-width/-height
# longhands automatically; the logical contain-intrinsic-block-size/-inline-size
# stay disabled-for-content (only un-gecko'd in longhands.toml to keep the
# contain-intrinsic-size logical group balanced for the servo build).
contain

# css-contain-3's `container-type` / `container-name` (and the `container`
# shorthand that sets both) are exposed so that `cqw`/`cqh` are a STANDARD
# implementation rather than viewport aliases: an element with
# `container-type: size | inline-size` is a size query container, and the
# container units resolve against the nearest such ancestor's content box,
# falling back to the small viewport only when there is none. Seeding the
# shorthand lets the closure pull both longhands in. The `@container` rule
# itself (https://drafts.csswg.org/css-contain-3/#container-rule) is NOT in
# scope -- it stays gecko-only in stylesheets/rule_parser.rs, so
# `container-name` is parsed and cascaded but nothing matches on it yet -- and
# `container-type: scroll-state` stays rejected behind its own static pref
# (`layout.css.scroll-state.enabled`, false).

# `scroll-capture` is a lynx-vello-only property with no W3C or Lynx

# chain.
